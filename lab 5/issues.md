# Lab 5 — Issue Table (billing_system.py)

| Issue | Type | Line(s) | Description | Fix Approach |
|---|---|---|---|---|
| Deprecated/weak crypto (ECB mode, PyCryptodome) | Security (Bandit B413, High) | 8, 73–75 (orig) | Card numbers were encrypted with AES-**ECB**, which produces identical ciphertext for identical plaintext (`encryptCard` returned `True` when called twice on the same card). PyCryptodome is also flagged as unmaintained by Bandit. | Switched to `cryptography`'s `AESGCM` with a random 12-byte nonce per call, so the same card number now encrypts to a different ciphertext every time. |
| XSS in rendered invoice | Security (Bandit B702, Medium) | 86–87 (orig) | `renderInvoice` fed the `user` field straight into a Mako template with no escaping, so a username like `<b onmouseover=alert(1)>ravi</b>` was rendered as live HTML. | Added Mako's `\| h` escape filter to both template variables, so user-controlled text is now HTML-escaped on render. |
| Insecure randomness for coupon codes | Security (Bandit B311, Low) | 68 | `random.choice` is not cryptographically secure and coupon codes are effectively a value a user could brute-force or predict. | Switched to the `secrets` module (`secrets.choice`), which is designed for tokens/codes that must not be guessable. |
| Hardcoded webhook secret | Security (Bandit B105, Low) | 14 | `WEBHOOK_SECRET` was a literal string baked into the source, so it ships with the code and can't be rotated without a redeploy. | Read it from `os.environ.get("WEBHOOK_SECRET", ...)`, with the old literal kept only as a fallback so the demo still runs without extra setup. |
| `assert` used for a runtime invariant | Security/Bug (Bandit B101, Low) | 86 | `assert amount >= 0` is stripped out entirely when Python is run with `-O`, so the check silently disappears in optimized builds. | Replaced with an explicit `if amount < 0: raise ValueError(...)`, which always runs. |
| Off-by-one in retry loop | Bug | 51–55 | `while attempts <= MAX_ATTEMPTS` let the loop run `MAX_ATTEMPTS + 1` times (4 attempts when `MAX_ATTEMPTS = 3`). | Changed to `for attempts in range(1, MAX_ATTEMPTS + 1)`, which runs exactly `MAX_ATTEMPTS` times. |
| `return` inside `finally` swallows the real logic | Bug (Pylint W0150/W0134/E0601) | 61–65 | `cancelRefund` always returned `price` in full, no matter how many days the user had used, because the `return` in `finally` discards anything before it; `days_used` was never actually applied, and the trailing `print` was dead code. | Removed the `try/finally`; the refund is now pro-rated as `price * (BILLING_CYCLE_DAYS - days_used) / BILLING_CYCLE_DAYS`. |
| Coupon can exceed 100% and produce a negative invoice | Bug | 28–33 | `FRIENDS150` is a 150%-off coupon with no cap, so `invoiceAmount` returned a **negative** total (`-294.41`). | Capped the discount at `min(coupon["percent"], 100)` in `apply_coupon`. |
| XXE-prone XML parsing | Security hardening | 81–83 | `lxml.etree.fromstring` on an external webhook payload is vulnerable to XML External Entity (XXE) attacks if an attacker controls the payload. | Switched to `defusedxml.ElementTree`, which parses safely by rejecting external entities/DTDs by default. |
| Style/quality: naming, docstrings, mutable literals, line length | Pylint/Flake8 (style) | throughout | `camelCase` function names, missing docstrings, `list()`/`dict()` instead of literals, lines over 79/100 chars, multiple imports on one line, unused `os`/`sys` imports, `== None` instead of `is None`. | Renamed all functions to `snake_case`, added docstrings, switched to literal `{}`/`[]`, wrapped long lines, split imports, removed unused imports, used `is None`. |

**Result:** Pylint 4.43/10 → **10.00/10**. Bandit: 1 High + 1 Medium + 3 Low → **0 High, 0 Low, 1 Medium** (the remaining Mako finding is a known Bandit limitation — it flags any `Template()` call regardless of the `\| h` filter actually present; see reflection). Flake8: 34 findings → **0**.
